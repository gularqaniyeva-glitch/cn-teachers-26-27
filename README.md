# ЦН обучение 26/27 — панель администратора

Внутренний веб-инструмент для администраторов, работающих с большой таблицей учителей
(в перспективе — около 6000 записей). Источник данных — Google Sheets.

## Стек

- **React 18 + TypeScript** — компонентный UI с проверкой типов.
- **Vite** — сборка и dev-сервер.
- **React Router** — навигация между разделами.
- **Zustand** — хранение состояния списка учителей.
- **Tailwind CSS v4** — стили.
- **lucide-react** — иконки.
- **Vercel Serverless Function** (`api/sheets.js`) — читает Google Sheets на сервере,
  используя сервисный аккаунт Google, не раскрывая ключ доступа в браузере.

## Подключение к Google Sheets

Приложение читает данные через собственную serverless-функцию `api/sheets.js`,
которая обращается к таблице от имени **сервисного аккаунта Google**. Это значит:

- Таблицу **не нужно** делать общедоступной по ссылке.
- Секретный ключ сервисного аккаунта хранится только в переменных окружения Vercel
  и никогда не попадает в код, который отправляется в браузер.

### Шаг 1 — создать сервисный аккаунт (в Google Cloud Console)

1. Откройте [console.cloud.google.com](https://console.cloud.google.com), создайте
   проект (или используйте существующий).
2. **APIs & Services → Library** → включите **Google Sheets API**.
3. **APIs & Services → Credentials → Create Credentials → Service Account**.
4. Внутри аккаунта откройте вкладку **Keys → Add Key → Create new key → JSON** —
   скачается файл с ключом. Он понадобится один раз, дальше храните его в надёжном
   месте (не в git-репозитории).
5. Скопируйте email сервисного аккаунта (вида
   `имя@проект.iam.gserviceaccount.com`) — он есть и в самом JSON-файле, и на странице
   аккаунта.

### Шаг 2 — открыть таблицу сервисному аккаунту

В самой Google Sheets таблице нажмите **Настройки доступа (Share)** и добавьте email
сервисного аккаунта с правом **Читатель (Viewer)**. Таблица при этом остаётся закрытой
для всех остальных — доступ есть только у этого технического аккаунта.

### Шаг 3 — задать переменные окружения на Vercel

В настройках проекта на Vercel (**Settings → Environment Variables**) добавьте:

| Переменная | Значение |
|---|---|
| `GOOGLE_SHEET_ID` | ID таблицы — часть ссылки между `/d/` и `/edit` |
| `GOOGLE_SERVICE_ACCOUNT_EMAIL` | email сервисного аккаунта из шага 1 |
| `GOOGLE_PRIVATE_KEY` | значение `private_key` из скачанного JSON-файла, целиком, включая строки `-----BEGIN PRIVATE KEY-----` / `-----END PRIVATE KEY-----` |

Необязательно (если названия вкладок в вашей таблице отличаются от значений по
умолчанию):

| Переменная | Значение по умолчанию |
|---|---|
| `GOOGLE_SHEET_TEACHERS_TAB` | `Все учителя 26/27` (2–9 классы) |
| `GOOGLE_SHEET_SENIOR_TAB` | `ИТ классы 25/26` (10–11 классы) |

После добавления переменных сделайте **Redeploy** проекта на Vercel, чтобы serverless-
функция подхватила их.

### Сопоставление колонок

Файл `src/services/sheetMapping.ts` ищет нужные поля **по названию заголовка**
(регистр и лишние пробелы не важны), перебирая несколько вероятных вариантов
(русский/азербайджанский/английский). Если в реальной таблице заголовок называется
иначе — допишите вариант в список `FIELD_CANDIDATES` в начале файла, менять остальной
код не нужно.

Колонки модулей должны называться `M1`, `M2`, … (ровно столько, сколько модулей в
программе параллели — см. `src/data/constants.ts`). Пустая ячейка модуля = статус
«не начал»; число (например, `85` или `85%`) = результат в процентах.

## Как запустить локально

Нужен установленный [Node.js](https://nodejs.org) (LTS, версия 18+).

```bash
npm install
npm run dev
```

Приложение откроется на `http://localhost:5173`.

**В режиме локальной разработки** serverless-функция `/api/sheets` недоступна (её
поднимает только Vercel), поэтому приложение автоматически покажет тестовые данные
(`src/data/mockTeachers.ts`, 50 вымышленных учителей) — в консоли браузера будет видно
предупреждение об этом. На собранном и задеплоенном на Vercel сайте вместо этого будут
подтягиваться реальные данные из таблицы.

Другие команды:

```bash
npm run build    # проверка типов + сборка production-версии в папку dist/
npm run preview  # локальный просмотр собранной версии
```

## Важные ограничения текущей версии

- **Запись обратно в таблицу не реализована.** Редактирование карточки, заметки и
  массовые действия сохраняются только в памяти текущей вкладки браузера — при
  обновлении страницы данные подтянутся заново из Google Sheets, и локальные правки
  потеряются. Полноценная запись изменений в таблицу — следующий шаг интеграции.
- **Дедлайны модулей временно отключены** — в источнике данных пока нет вкладки с
  датами сдачи. Успеваемость считается от всех назначенных модулей программы, без
  учёта сроков. Модель дедлайнов (`src/utils/deadlines.ts`) готова и подключится
  обратно, когда появится реальный календарь.
- Сайт на Vercel сейчас **не защищён паролем** — это стоит иметь в виду, так как в
  таблице реальные персональные данные (ФИО, FIN, телефон).

## Авто-аудит аномалий LMS

Приложение автоматически ищет два типа вероятных технических сбоев выгрузки:

- **Индивидуальная аномалия** — учитель сдал больше 70% модулей своей программы, но
  один конкретный модуль всё ещё «не начат». Помечается статусом «🔍 На проверку».
- **Групповая аномалия** — в конкретном модуле у целой группы (параллель + сектор +
  формат обучения, минимум 3 учителя) более 80% значений «не начал», хотя по остальным
  модулям та же группа показывает хороший прогресс. Помечается как «⚠️ Подозрение на
  сбой LMS».

Обе аномалии видны построчно в карточке учителя и в «Отчёте по модулю», а также
собраны в отдельном виджете на странице «Статистика» с экспортом в CSV.

## Модули обучения

- 2–4 классы: `M1`–`M6`
- 5–9 классы: `M1`–`M13`
- 10–11 классы (отдельная вкладка меню, отдельный источник — лист «ИТ классы 25/26»):
  `M1`–`M8`

Три статуса модуля: 🟢 Сдал / 🔴 Не сдал / ⚪ Не начал, плюс производный
диагностический статус 🔍 На проверку (см. «Авто-аудит аномалий LMS» выше).
